# Процесс и уроки — читать перед любой работой с роликами

Документ собран по итогам копии образца 01 («Отёки ног»), 2026-10-09. Здесь — как работаем сейчас,
что пользователь поправлял и какие ошибки уже были. Новый урок — дописывать сюда сразу, в тот же коммит.

## 0. Режим «под ключ» (с 2026-10-09)

Пользователь: «Делай все сам под ключ». Ролик делаю целиком сам, без промежуточных вопросов:
тема → сценарий → кадры героя → клипы Grok → сборка на сервере → проверка (раздел 4) →
исправления (перегенерация плохого плана, бесплатные правки сборки) → отправка.
- Деньги: до **5 $ на ролик** включая переделки — не спрашивать; в отчёте — итог по расходам.
  Если видно, что выйдет больше, — остановиться и спросить.
- В конце присылать: готовое видео 720 и 1080 до 30 МБ (шаг `share`), коротко — сценарий,
  что проверено, что исправлено, что может проверить только пользователь (голос между клипами).
- Тема: польза для здоровья семьи в стиле «народных подсказок», но **без ложных медицинских
  обещаний**; где уместно — когда идти к врачу. Финал — призыв «напишите слово «книга»».

## 1. Правила пользователя (не нарушать)

1. **Монтаж и рендер — только на сервере Railway** (проект `lekar`). Генерация — на fal. В сессии ffmpeg —
   только на маленьких кусках для проверки. Пользователь повторял это много раз.
2. **Работаем только в Lekar.** Другие проекты на Railway и в GitHub не трогаем.
3. **Деньги:** перед любым платным шагом — таблица: цена теста и цена всего ролика, по каждой модели.
   Дорогие модели не тестировать без прямой просьбы. Запускать после «да»/«делай».
   Самое дешёвое приемлемое качество — по умолчанию (пример: «480 естественно»).
4. **Сначала короткий тест (15–20 с), потом весь ролик.**
5. **Всё делаем в Grok** (`xai/grok-imagine-video/image-to-video` на fal, 0,05 $/с):
   каждый план — клип Grok **со своей речью**. Если в плане героя не видно или он не должен говорить —
   голос **за кадром**, но тоже из Grok (`"speech": "voiceover"` в shots.json). Отдельную озвучку
   (ElevenLabs) и подклейку голоса/синхронизацию губ больше не используем.
6. **Плохой план — перегенерировать этот план в Grok целиком**, а не латать поверх (lipsync, маски и т.п.).
7. **Наш герой должен отличаться от оригинала:** футболка оливковая с мультяшной обезьяной и надписью
   «ХРЕН ИИШНЫЙ» над ней. Лист персонажа: `assets/hero/character_sheet_v2.png`.
8. **Присылать файлы:** готовое видео отдельно и «оригинал | копия» отдельно; по просьбе — каждый клип
   отдельно. Ссылки на сервер в чат не давать (в них токен). Лимит файла в чат — 30 МБ.
9. **Перед отправкой проверять самому:** расшифровка, стыки, субтитры, кадры каждого плана (раздел 4).
10. **Качество поднимать бесплатно** там, где можно (ffmpeg на сервере), до предложения платного.

## 2. Как делаем ролик сейчас (конвейер Grok)

```bash
# 0. образец: samples/<id>/{original.mp4 → на сервер, text.txt, shots.json, prompts.yaml}
python3 tools/remote.py put original.mp4 samples/<id>/original.mp4
# изменённые text/shots/prompts тоже класть на сервер: при старте он НЕ перезаписывает файлы на диске

# 1. кадры героя (Nano Banana Pro edit, 0,15 $/шт): кадр оригинала + лист персонажа → тот же кадр,
#    наш герой в футболке, без зашитых субтитров. work/<id>/A/frame_N.png (+ на сервер)

# 2. клипы Grok со своей речью, расшифровка, план сборки → сервер
python3 tools/grok_build.py <id> [--shots 1 2 3] [--redo 3]          # без --yes только расчёт
python3 tools/grok_build.py <id> --shots 1 2 3 --yes

# 3. сборка на сервере: склейки, звук из клипов, субтитры, улучшение картинки, 720 и 1080, сравнение
python3 tools/remote.py run <id> assemble_g && python3 tools/remote.py wait <id>

# 4. проверка (раздел 4), потом копия для чата и отправка
python3 tools/remote.py run <id> share && python3 tools/remote.py wait <id>   # replica_*_1080_chat.mp4 ≤ 29 МБ
```

- Длина клипа Grok: короткий план — длина плана в оригинале, вверх до целых секунд; часть длинного
  плана — `ceil(слова / 2,4 + 0,3)`. Максимум Grok — 15 с.
- План длиннее ~12 с — делить по фразам (`grok_parts` в shots.json); каждая следующая часть стартует
  с **последнего кадра предыдущей**, поэтому поза на стыке не прыгает.
- Склейка ставится как в оригинале, если речь в неё влезает; иначе — через 0,25 с после конца речи.
- Промпт Grok: действие из `prompts.yaml → grok`, плюс точная фраза в кавычках, описание голоса
  (мужской, ~55 лет, тёплый, с хрипотцой), темп ~2,3 слова/с, «без музыки, без текста на экране».
- Метку генератора ✦ на кадре закрывает `delogo` (координаты в shots.json, сетка 720×1280).

## 3. Ошибки, которые уже были, и как их не повторять

### Генерация
| Ошибка | Правило |
|---|---|
| Grok растянул фразу на весь клип — говорил медленно (1,58 сл/с вместо 2,05) | Клип не длиннее речи: длина по числу слов; в промпте темп |
| Grok льёт уксус сплошной струёй сквозь ложку | Действие расписывать по шагам и прямо запрещать лишнее: «наливает, пока ложка не наполнится, ставит бутылку, наклоняет ложку; ничего не переливается» |
| Grok добавил вторую ложку, лишний лимон, лампу | В промпте полный список предметов и «никаких новых предметов» |
| Я сам велел Grok молчать в планах 2–3, а в оригинале герой там говорит | Сверять по оригиналу, говорит ли герой в каждом плане |
| Части длинного плана прыгали на стыке: клип обрезался после речи, а следующая часть стартует с последнего кадра клипа | Часть, за которой идёт продолжение, брать до последнего кадра (assemble_g так и делает) |
| Даже при цепочке кадров стык частей заметен: Grok перерисовывает стартовый кадр (цвет/масштаб), разница ~8 против ~2,5 внутри клипа | На стыке частей — растворение последнего кадра предыдущей части за 0,25 с (assemble_g) |
| Fabric не показывает на ногу — он не принимает промпт, жест случайный | Если важен жест — модель с промптом (Grok/Kling) |
| Veo 3.1 отклоняет наши кадры модерацией (даже с нейтральным текстом) | Veo для этого героя не годится; не тратить попытки |
| Sora: OpenAI отвечает 404 на Videos API | Доступ не открыт на аккаунте OpenAI; не планировать Sora |
| Kling 3 / 2.6: голос только китайский/английский | Для русской речи не годятся |
| Nano Banana отклонил промпт со словами «убрать водяной знак» | Писать «без текста на изображении», про метки не упоминать; ✦ закрывать delogo |
| Пилот n01, кадр 8: на тарелке пирожки вместо котлет (промпт «golden cutlets») | Блюдо описывать по форме и с запретом похожего: «round flat fried minced-meat patties, not pies, not pastries»; каждый кадр смотреть — блюдо то, что по рецепту, ДО генерации клипа |

### Звук и субтитры
| Ошибка | Правило |
|---|---|
| Повтор хвоста «шага» на склейке: кусок голоса резался **после** atempo | В ffmpeg `-ss/-t` ставить **до** `-i`, если дальше есть фильтр темпа |
| Тайминги ElevenLabs пришли кусками, слова на стыках порезаны («одн|у») | Склеивать посимвольные куски до разбора на слова |
| Тире «--», «–» считались словами | Слова — только буквы/цифры, дефис только внутри слова; знаки из расшифровки выкидывать |
| whisper-1 слышал «бога под», «покамогает», «Копните» — а Grok сказал верно | Перед перегенерацией перепроверять текст `gpt-4o-transcribe` (grok_build делает сам); whisper — только для таймингов |
| Правка кода в фоновой команде упала на assert, а я счёл её применённой — и перегенерировал по ложной тревоге | После правки проверять grep'ом, что она в файле; правки не смешивать в одной команде с долгой работой |
| Скачивание готового клипа оборвалось (RemoteDisconnected) | Клип уже оплачен: забрать по request id из ledger, не генерировать заново |
| Whisper ставит первому слову после тишины начало 0 → субтитр раньше на 0,4–0,9 с | Начало первого слова клипа брать по громкости (`speech_onset`) и проверять по ней |
| Субтитры мельче оригинала: размер ASS ≠ высота букв | Подбирать размер по замеру ширины одного и того же слова в кадре оригинала (сейчас 66) |
| Размер субтитров «на глаз» по уменьшенному листу кадров | Судить о размерах только по полному кадру 720×1280 и замеру |

### Сервер и процесс
| Ошибка | Правило |
|---|---|
| Пуш перезапустил сервер посреди платного шага | После пуша ждать `SUCCESS` на новом коммите, потом запускать шаги; во время шага не пушить. Оборванный запрос fal забирать по request id, не платить второй раз |
| Сервер не перезаписывает образцы на диске — шёл старый shots.json | После правки text/shots/prompts — `remote.py put` на сервер |
| Шаг упал — не записался meta.json, следующий шаг сломался | После сбоя проверять, какие файлы шаг должен был оставить |
| Деплой падал: сборщик Railway не мог скачать `python:3.11-slim` с Docker Hub; повтор через API собирал Railpack'ом мимо Dockerfile | Базовый образ — из зеркала `public.ecr.aws/docker/library/…`; после пуша проверять, что деплой именно `SUCCESS` на новом коммите, а не старая сборка |
| Имя шага с «_» отклонялось сервером (404) | Новые шаги проверять запуском сразу после деплоя |
| Склейка клипов разной ширины без перекодирования показала один клип | Перед склейкой приводить всё к 720×1280, 24 к/с, 44,1 кГц |
| Ссылка на файл содержит токен сервера | В чат — только файлы; >30 МБ — сжатая копия |
| Скрытые файлы (`.claude/`, `.dockerignore`) пропали при загрузке навыка в claude.ai | В навыках хранить без точки и возвращать точку при копировании |
| `rm -f $D/$f` блокируется проверкой безопасности | Писать `"${D:?}/${f:?}"` |

## 4. Проверка перед отправкой (обязательно)

1. **Текст:** расшифровка итогового звука (whisper) против сценария — пропуски, лишние, повторы.
   Сомнительное слово — назвать время, чтобы пользователь послушал.
2. **Стыки:** сходство звука до/после каждой склейки < 0,6 (повтор давал 0,69, норма 0,1–0,4);
   у частей одного плана — разница кадров на стыке как внутри клипа (~2–5).
3. **Субтитры:** каждое слово против речи; > 0,3 с — проверить по громкости, прежде чем верить whisper.
   Размер и положение — замером на полном кадре.
4. **Кадры:** лист кадров каждого плана — действие как в оригинале, рот двигается там, где он говорит,
   нет лишних/пропавших предметов, лицо и футболка одинаковые.
   Еда в кадре — именно то блюдо, что в рецепте (котлеты ≠ пирожки), и на этом же этапе готовки.
5. **Техника:** длина, склейки против оригинала (±0,3 с, где возможно), громкость −14 LUFS.
6. **Героиня:** высота голоса каждого клипа 183 ± 15 Гц (автокорреляция по громким кускам); выпал — перегенерировать план.
   Табличка расчёта (check.json) не закрывает лицо, итог совпадает с тем, что она говорит.
7. В ответе — честно: что проверено, что не совпало, что может проверить только пользователь
   (одинаковость голоса между клипами Grok).

## 6. Дубликат чужого ролика — пошагово (обкатано на 03–05, 2026-10-09)

1. **Разметка оригинала** (бесплатно):
   `python3 tools/dup_prepare.py <id> --yadisk <ссылка на папку> --path /<файл>.mp4` (или `--file`).
   Даёт текст, склейки (порог 0,08 — на 0,25 пропускаются склейки внутри одной обстановки), текст по
   планам и лист стартовых кадров `work/<id>/src/sheet.jpg`. Оригинал — на сервер:
   `remote.py put work/<id>/src/original.mp4 samples/<id>/original.mp4`.
2. **Раскадровка** `samples/<id>/shots.json` — по склейкам оригинала:
   - каждый план с действием (ингредиент, жест) — отдельный план со своим стартовым кадром;
   - подряд идущие планы с той же рамкой («говорит со стаканом», лёгкие подъезды камеры) — **один**
     план с `grok_parts` (части по фразам, 6–12 с, цепочка кадров): меньше стартовых кадров, голос
     меняется реже, стык сглаживает растворение;
   - `delogo` [572,1128,60,60] на всех планах — метка ✦ генератора.
3. **Текст** — тот же по структуре и длине фраз, что в оригинале (хук, рецепт, призыв «книга»),
   но ложные медицинские утверждения переписать честно («в аптеках не любят», «забитый кишечник»,
   «расщепляет застои», «почки перегружены» → по фактам), добавить «когда к врачу», где есть риск.
   Сомнительные дозировки смягчать (столовая ложка гвоздики → щепотка). Фразы короткие и простые:
   на трудных конструкциях Grok оговаривается.
4. **Действия** `samples/<id>/prompts.yaml → grok`: что делает герой, только предметы и люди из кадра,
   «no new objects appear». Второй человек (девушка в 05) сохраняется из кадра оригинала.
5. **Кадры героя**: `python3 tools/hero_frames.py <id> --yes` (0,15 $/кадр, 6 параллельно) → лист кадров
   глазами → `--redo N` для кадров с остатками субтитров оригинала.
6. **Клипы**: `python3 tools/grok_build.py <id>` (расчёт) → `--yes`. Три ролика можно гнать параллельно
   (разные папки). Текст проверяется whisper, при расхождении — `gpt-4o-transcribe`; перегенерировать
   только то, что не подтвердилось второй расшифровкой (`--redo 7.1`).
7. **Сборка и копия для чата** на сервере: `run <id> assemble_g`, затем `run <id> share`.
8. **Проверка** (раздел 4) и отправка: 1080 до 30 МБ, отчёт — что изменено в тексте, что проверено,
   расходы по ролику.

Бюджет по опыту: кадры 7–11 × 0,15 $ + Grok 45–60 с × 0,05 $ ≈ **3,3–4,7 $ на ролик** до переделок.
